# Security Policy

## Reporting a vulnerability

Please do not publish an exploitable vulnerability, proof of concept, secret, or affected-user data in a public GitHub issue.

If GitHub shows **Security → Report a vulnerability** for this repository, use that private vulnerability reporting form. Include the affected component and version or commit, impact, reproduction conditions, and any suggested mitigation.

If private vulnerability reporting is unavailable, open a public issue containing no vulnerability details and ask the maintainer to arrange a private contact channel. Do not attach an exploit or describe the vulnerable path in that issue.

There is currently no published response-time SLA or formal supported-version schedule. Reports will be assessed according to impact and the project's development status.
