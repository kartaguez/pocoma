# L2 — Manifeste de couverture de certification

**Statut : préparation P0 ; aucune méthode implémentée ou exécutée, aucun PASS L2 ou global.** Référence : [SPEC-10](SPEC-10_Test_Certification.md), [R1–R10](L2_R1_R10_Normative_Consolidation.md), [contrat L1-C](L1_C_Transaction_Contract.md), [L1-F](L1_F_Closure_Report.md), [L1-F2](L1_F2_Invariant_Matrix.md). Ce manifeste alloue les obligations sans modifier leurs oracles normatifs. Le plan des étapes/gates est dans le [plan L2 §14](L2_Design_and_Verification_Plan.md#14-vérification-future-gates-provenance-et-critères-de-sortie).

Une ligne **obligatoire L2** désigne une preuve à produire sur le sujet indiqué. « Banc technique » et « fixture » ne certifient jamais le composant métier absent. Une ligne **reporté** garde le même identifiant normatif et désigne le lot receveur ; ce report ne vaut jamais PASS. Les méthodes nommées sont toutes **prévisionnelles** et doivent être reliées plus tard à une méthode réellement exécutée, ses XML, SQL, traces et SHA. Un oracle indépendant utilise un snapshot PostgreSQL extérieur après résolution, des barrières et horloges DB pour les courses, ou un inventaire statique contrôlé pour les contrats documentaires. Aucun résultat n'est inventé ici.

Les identifiants C01…C06 et E01…E03 sont ceux des tables de SPEC-10. Les compléments non lettrés de CON-05 conservent **CON-05** dans la colonne normative et reçoivent chacun un identifiant de preuve distinct. Les suffixes de preuve décomposent les variantes composées sans créer de nouvelle exigence métier. Les reports L3–L6 suivent les lots du [plan directeur](V3_Implementation_Master_Plan.md). P1–P8 et G1–G3 sont des campagnes/gates **futurs** ; P0/G0 relisent ce manifeste avant code.

## Contrôle inverse et provenance future

À P0/G0, extraire les ID C01-A…L, C02-A…L, C03-A…L, C04-A…L, C05-A…M, C06-A…P, E01-A…H, E02-A…J, E03-A…J de SPEC-10 et les clauses R1-01…R10-11 de la consolidation ; comparer les ensembles aux identifiants normatifs ci-dessus, puis contrôler séparément les compléments CON-05 et L1-C/F/F2. Vérifier unicité des identifiants de preuve, oracle non vide, allocation et report motivé, campagne/gate, méthode explicitement prévisionnelle. Le script [check_l2_manifest.py](check_l2_manifest.py) réalise ces contrôles statiques sur les sources du dépôt et calcule les nombres réels.

Après implémentation, chaque méthode exécutée devra référencer son identifiant de preuve dans le nom ou les métadonnées de campagne. Le collecteur confrontera **manifeste → méthodes présentes → XML frais → oracle SQL/trace → SHA/commande** et **méthodes XML → identifiant de preuve connu**. Absence, skip, fixture seule ou provenance manquante donnent INCONCLUSIVE pour la contribution concernée ; violation donne FAIL. Une nouvelle variante de SPEC-10 ou clause Rn exige une ligne avant campagne. Aucun report ne devient PASS sans réalisation du composant du lot receveur et sa propre preuve indépendante.
