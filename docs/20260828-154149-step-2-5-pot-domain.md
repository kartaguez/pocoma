# Étape 2.5 — Renommage et clarification de domain-pot

## Objectif

Transformer le module générique `domain` en domaine Pot explicite, sans changement métier :

```text
domain → domain-pot
pocoma-domain → pocoma-domain-pot
com.kartaguez.pocoma.domain.* → com.kartaguez.pocoma.domain.pot.*
```

Tout le contenu actuel reste dans `domain-pot`, y compris les identifiants, `UserId` et les
valeurs génériques. Leur éventuelle extraction sera décidée ultérieurement.

## Migration

1. Renommer le module, son artifact et toutes les dépendances Maven.
2. Déplacer aggregate, association, created, draft, entity, exception, factory, value et les deux
   représentations Shareholder sous `domain.pot`.
3. Adapter les imports par nom pleinement qualifié, sans déplacer les classes du module séparé
   `domain-projection`.
4. Retirer Lombok, inutilisé, afin que le code principal dépende uniquement du JDK.
5. Ajouter des règles ArchUnit propres à `domain-pot` et interdire les anciens packages.
6. Valider chaque dépendant puis le build agrégé.

## Limites

Les événements restent dans `engine-core` jusqu'à 2.6. Les pipelines et tâches restent dans
`domain-pipeline-tasks` jusqu'à 2.7. Aucun schéma SQL, JSON, endpoint ou comportement n'est modifié.
