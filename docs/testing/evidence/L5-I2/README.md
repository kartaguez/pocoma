# Preuves L5/I2

Les archives `archives/*.tar.xz` contiennent les fichiers du répertoire de campagne : plan et argv Maven exacts, modèle effectif, provenance/empreintes, XML neufs par module/producteur, logs, compteurs, phases temporelles et éventuelles observations SQL/Bruno. L’[index](archives.json) donne chemin, taille et SHA-256 de chaque export.

Chaque archive contient `publication-map.json`, avec empreintes et tailles original → publication. Les verdicts, compteurs, identités, commandes et durées ne sont jamais réécrits. Seules les valeurs reconnues comme secrètes sont expurgées ; le nombre exact est indiqué dans l’index. Les enveloppes `raw.tar.gz` du collecteur sont retenues également, avec la même expurgation documentée et leurs empreintes original/publication : aucune réutilisation de XML historique comme nouvelle preuve.

Les répertoires initiaux se trouvent sous `/private/tmp/` et restent attribués à leurs invocations originales. Un PASS CLI d’un essai ne clôt pas les autres FAIL/INCONCLUSIVE. Notamment : les essais initiaux dans le worktree contrôlé par JDT sont diagnostiques ; `d4-02`, exécuté par erreur dans ce worktree, n’est pas retenu comme qualification malgré son résultat CLI. Le D4 isolé et son complément final sont les références de calibration. `c-01` est un FAIL d’exécution interrompue pour corriger le profil du contrôleur, avec zéro échec d’assertion parmi ses rapports partiels ; il ne satisfait pas la gate. `c-02` est un FAIL complet du reactor sélectionné (2120 tests exécutés, un échec `i5_w17`, 170 oracles Architecture non exécutés). Le diagnostic du helper d’attente, sa régression pure et le rejeu physique causal sont distincts ; ils ne réétiquettent pas C-02. C-03 est un FAIL d’exécution interrompue après 1675 tests réussis, à la suite de l’alias Unicode démontré en revue ; les sources originales et la reproduction Java sont conservées, puis les méthodes pures/HTTP sont enrichies sans suppression d’oracle.

Les sources I2 sont qualifiées dans un worktree isolé pour garantir le propriétaire unique de `target`. Le [reçu EOL](checkout-eol.json) explique le seul écart de checkout initial (wrapper Windows CRLF déclaré par `.gitattributes`, blob Git normalisé inchangé). Les empreintes de tous les inputs applicatifs sont comparées au worktree de livraison ; le SHA de commit seul n’est jamais substitué à cette comparaison.

Le [registre H](historical-reuse.json) conserve l’attribution des fondations et ses comparaisons ; le [relevé d’environnement](toolchain.json) distingue les versions réelles et l’AuthN locale de fixture du fournisseur non qualifié. Inventaires, verdict technique final et réserves : rapport/manifeste I2 sous `docs/v3/`. Aucune certification SPEC-10 ou clôture humaine n’est déduite d’une archive.
