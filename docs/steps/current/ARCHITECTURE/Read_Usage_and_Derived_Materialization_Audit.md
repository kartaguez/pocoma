## 2. Lecteurs et matrice principale

Abréviations : `E` = identité externe `(issuer,subject)`, `U` = user interne, `B` = occurrence de binding, `R` = révision binding, `V` = version Pot. « Exact » signifie une clé fournie, pas une recherche du courant. `root/artifact` désigne les tables canoniques READ [V7](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V7__canonical_projection_store.sql). Pour les quatre types de projection actuels, la route Event→Task vient de [PocomaProjectionMaterializationPolicy](../../../../app/runtime-event-consumption-worker/src/main/java/com/kartaguez/pocoma/runtime/event/consumption/PocomaProjectionMaterializationPolicy.java), le catalogue de [CanonicalProjectionTaskRuntimeConfiguration](../../../../app/runtime-task-consumption-worker/src/main/java/com/kartaguez/pocoma/runtime/task/consumption/CanonicalProjectionTaskRuntimeConfiguration.java), et la lecture exacte de [ExactProjectionReadService](../../../../app/engine-projection-read/src/main/java/com/kartaguez/pocoma/engine/service/projection/read/ExactProjectionReadService.java).

### Données de support et limites d'exposition

Les lignes `projection_root` et `projection_artifact` sont les conteneurs partagés des quatre sorties effectives, non un résultat métier supplémentaire : `root` porte la clé exacte et `artifact` le JSON de valeur. `projection_failure` porte des occurrences de défaillance, sans effacer un root. [JdbcProjectionStoreAdapter](../../../../app/infra-projection-persistence/src/main/java/com/kartaguez/pocoma/infra/projection/persistence/JdbcProjectionStoreAdapter.java) lit le root par quatre composantes, puis tous ses artifacts triés techniquement ; il teste l'échec seulement si aucun root n'est trouvé. [V7](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V7__canonical_projection_store.sql) définit les clés et l'index d'échec.

Le [READ V6](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V6__pot_version_metadata_and_user_index.sql) créait `pot_projection_user_index` (listing paginé par U) et un `pot_version_metadata` READ ; [V8](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V8__drop_legacy_read_projection_structures.sql) les supprime avec `pot_projection_snapshots`, ses composants, anciens artifacts/failures/heads. Ce sont des traces historiques, **pas** des objets READ actuels. Le metadata actuel `pot_version_metadata` est dans le primaire [WRITE V11](../../../../app/infra-persistence-jpa/src/main/resources/db/migration/V11__pot_version_metadata.sql) : `(potId,V)→createdAt` immutable, écrit avec la version Pot par [JpaPotGlobalVersionAdapter](../../../../app/infra-persistence-jpa/src/main/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/JpaPotGlobalVersionAdapter.java) ; [JpaAuthProjectionInputLoader](../../../../app/infra-persistence-jpa/src/main/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/projection/JpaAuthProjectionInputLoader.java) vérifie sa présence avant reconstruction. Ce support de traitement n'est pas une API READ. Aucune primitive `MAX(version)`/`ORDER BY version DESC LIMIT 1` ne sert les GET READ actuels : ils exigent V explicitement ; le `ORDER BY ... DESC` de [READ V13](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V13__verify_terminal_binding_facts.sql) est un contrôle de migration, pas la requête HTTP du courant.

L'identité `E→U` lue par [PotQueryController](../../../../app/supra-http-read-query/src/main/java/com/kartaguez/pocoma/supra/http/read/query/PotQueryController.java) passe par `ExternalIdentityResolverPort` et [JpaExternalIdentityResolverAdapter](../../../../app/infra-persistence-jpa/src/main/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/identity/JpaExternalIdentityResolverAdapter.java), qui interroge l'autorité primaire `external_identities`, avant AUTH@V. Ce GET pose une question courante et utilise seulement U ; contrairement au self GET binding, il ne consulte pas `CURRENT_BINDING`. Le worker Command relit, lui, l'autorité primaire avec le **B exact** de l'enveloppe sous lock/fence via [ExecuteRecordedCommandService](../../../../app/engine-command/src/main/java/com/kartaguez/pocoma/engine/command/execution/ExecuteRecordedCommandService.java). Ces lectures ne sont pas des matérialisations READ supplémentaires ; elles sont indispensables à l'inventaire des consommateurs et des frontières. `TokenCapabilities` vient des autorités du JWT à l'appel, sans table READ de permissions dérivées ([ReadPotService](../../../../app/engine-pot-read/src/main/java/com/kartaguez/pocoma/engine/pot/read/ReadPotService.java)).

La découverte effective [JdbcProjectionMaterializationDiscoveryAdapter](../../../../app/infra-persistence-jpa/src/main/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/processing/event/JdbcProjectionMaterializationDiscoveryAdapter.java) fait `UNION ALL` des Business Events Pot et des terminal Events Command ; aucun fact Binding n'y figure. [ProjectionMaterializationConsumptionService](../../../../app/locator-consumption-event/src/main/java/com/kartaguez/pocoma/locator/consumption/event/materialization/ProjectionMaterializationConsumptionService.java) assure la Task dans la transaction de finalisation du slot Event. [ProjectionTaskConsumptionService](../../../../app/engine-projection-task/src/main/java/com/kartaguez/pocoma/engine/projection/task/ProjectionTaskConsumptionService.java) prépare, puis publie ou enregistre l'échec dans la transaction fenced du slot Task. Le chargement peut précéder cette finalisation ; le commit autoritatif, celui de la Task et celui du READ sont distincts.

## 5. Trois objets à examiner séparément

### LATEST_KNOWN_VERSION

La table physique conserve le nom historique `source_version_watermarks`. [READ V4](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V4__add_source_version_watermarks.sql) définit une seule ligne `(pot_id,latest_version_seen,advanced_at)` par Pot. Le [locator](../../../../app/locator-consumption-latest-known-version/src/main/java/com/kartaguez/pocoma/locator/consumption/latestknownversion/LatestKnownVersionConsumptionLocator.java) découvre les Events, recharge l'Event exact et fournit sa version au service d'avance. L'[adapter](../../../../app/infra-read-persistence/src/main/java/com/kartaguez/pocoma/infra/read/persistence/JdbcLatestKnownVersionAdapter.java) fait un upsert seulement si le candidat est supérieur, sinon relit la ligne et retourne `Unchanged`. La transaction de Consumption et le CAS lient l'avance, la provenance et le terminal slot ; le commit de l'Event est antérieur. Les [tests SQL](../../../../app/infra-read-persistence/src/test/java/com/kartaguez/pocoma/infra/read/persistence/LatestKnownVersionPersistencePostgresTest.java) démontrent premier V potentiellement supérieur à 1, doublon, V inférieur, concurrence hors ordre et horodatage stable sans avance. Les [tests runtime](../../../../app/runtime-latest-known-version-consumption-worker/src/test/java/com/kartaguez/pocoma/runtime/latestknownversion/LatestKnownVersionRuntimePostgresTest.java) couvrent désordre, retry, rollback, claim perdu et absence de travail ProjectionTask. Les seuls lecteurs trouvés dans `src/main` sont le retour interne de l'adapter et son wrapper de métriques ; aucun GET ou loader de projection ne consulte le watermark. Sa raison d'exister observée est de conserver le maximum vu par ce consumer, pas de résoudre un artifact pour un appel métier. La continuité V1,V2,… n'est pas exigée par cet upsert.

### CURRENT_BINDING

L'autorité est le binding actif primaire plus son stream R et ses faits ; [JpaExternalIdentityBindingAdapter](../../../../app/infra-persistence-jpa/src/main/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/identity/JpaExternalIdentityBindingAdapter.java) écrit l'évolution autoritative et le fait dans sa transaction. Le [locator Binding](../../../../app/locator-consumption-binding/src/main/java/com/kartaguez/pocoma/locator/consumption/binding/BindingFactConsumptionLocator.java) découvre puis recharge par `event_id`, convertit ATTACHED en U/B et DETACHED en U/B nuls, et applique le READ sous finalisation de Consumption. Le [modèle](../../../../app/engine-read-projection/src/main/java/com/kartaguez/pocoma/engine/read/binding/CurrentBinding.java), les migrations [V11](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V11__current_binding_canonical_detached.sql), [V12](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V12__current_binding_fact_provenance.sql) et le gate [V13](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V13__verify_terminal_binding_facts.sql) établissent tombstone, provenance réelle y compris R0 et parité avec le dernier fait par E. Le GET self lit directement cette valeur sous E du principal, et cache DETACHED/absence. Le besoin de résolution préalable à une Command n'est pas actuellement servi par ce GET au POST : le client doit disposer de B, l'admission valide seulement sa forme et le worker Command vérifie E+B sur le primaire. Les [tests persistence](../../../../app/infra-read-persistence/src/test/java/com/kartaguez/pocoma/infra/read/persistence/CurrentBindingPersistencePostgresTest.java) et [runtime](../../../../app/runtime-binding-consumption-worker/src/test/java/com/kartaguez/pocoma/runtime/binding/BindingRuntimePostgresTest.java) démontrent désordre, duplicate, jump, retry, restart de scan, claim perdu et multi-worker. Contrairement à LKV, cette ligne transporte une valeur métier directement utile au GET, conserve le DETACHED et rejette les payloads divergents à R égal. Leur similitude physique est la condition `excluded.revision > current.revision`, non une preuve de même sémantique.

### COMMAND_RESULT

L'[outcome writer](../../../../app/infra-persistence-jpa/src/main/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/command/JdbcCommandOutcomeAdapter.java) insère l'outcome unique et son terminal Event dans le même commit Command ; [WRITE V17](../../../../app/infra-persistence-jpa/src/main/resources/db/migration/V17__command_outcomes_and_terminal_events.sql) contraint l'unicité par commandId. Le [loader](../../../../app/infra-persistence-jpa/src/main/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/projection/JdbcCommandResultProjectionInputLoader.java) recharge l'outcome puis l'E exacte capturée à l'admission sous lecture `REPEATABLE_READ`. Le [projector](../../../../app/engine-command-result/src/main/java/com/kartaguez/pocoma/engine/command/result/CommandResultProjector.java) émet un artifact JSON exact `commandId/1`, validé avant publication. Le [GET](../../../../app/engine-command-result/src/main/java/com/kartaguez/pocoma/engine/command/result/GetCommandResultService.java) exige l'E exacte et retourne NotFound si non-owner, non-prêt ou failure ; [READ V14](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V14__gate_command_result_exact_identity.sql) bloque les anciens artifacts sans ownership E exact au cutover. [CommandResultProjectionChainPostgresTest](../../../../app/architecture-tests/src/test/java/com/kartaguez/pocoma/architecture/ccr/CommandResultProjectionChainPostgresTest.java) et [CommandCompletionE2EPostgresTest](../../../../app/architecture-tests/src/test/java/com/kartaguez/pocoma/architecture/ccr/CommandCompletionE2EPostgresTest.java) prouvent le chemin terminal→Task→READ et les réponses. L'usage exige corrélation à un commandId, terminalité et ownership ; l'implémentation utilise techniquement route/Task/validator/root/artifact. Rien dans la question lue n'exige de sélectionner un état courant ou de comparer des versions successives.

## 6. Scénarios transversaux et ownership

**Command actuel.** JWT atteste E et fournit les autorités techniques. Un éventuel GET self binding peut donner B courant depuis READ, de façon asynchrone ; aucun appel interne au POST ne l'effectue. `POST Command(E,B,payload)` enregistre l'enveloppe sans résoudre U/B ni autoriser le métier, puis renvoie 202 ([AsyncCommandController](../../../../app/supra-http-write-command/src/main/java/com/kartaguez/pocoma/supra/http/write/command/AsyncCommandController.java), [CommandAdmissionPostgresTest](../../../../app/runtime-web-api/src/test/java/com/kartaguez/pocoma/CommandAdmissionPostgresTest.java)). Worker Command : recharge, verrouille l'occurrence **exacte** E+B sur l'autorité, calcule permissions/état, mute le Pot, append Business Event, écrit outcome+terminal Event et termine le claim dans le commit fenced ([ExecuteRecordedCommandService](../../../../app/engine-command/src/main/java/com/kartaguez/pocoma/engine/command/execution/ExecuteRecordedCommandService.java), [CommandConsumptionPostgresTest](../../../../app/infra-persistence-jpa/src/test/java/com/kartaguez/pocoma/infra/persistence/jpa/adapter/command/CommandConsumptionPostgresTest.java)). Ensuite Event→Task→COMMAND_RESULT READ, et, en cas de Business Event, trois Tasks Pot@V. Le demandeur lit COMMAND_RESULT par id ; pour le Pot, il donne `potId,V`, mais le GET résout actuellement E→U dans le primaire avant AUTH@V et READ_POT@V. Un détenteur d'un commandId appartenant à un autre E obtient 404. Un B faux/ancien n'est pas accepté comme autorité au worker même si le POST a donné 202.

**Registration documenté, non livré.** Le [Canon](../REGISTRATION/Step_Canon.md) et le [Plan](../REGISTRATION/Step_Plan.md) cadrent `POST` JWT/E → request immutable seule/202 ; worker Registration → outcome Registered(U,B) ou Rejected, avec sur succès création U, binding autoritatif, faits `UserCreated` et `ExternalIdentityAttached` dans son commit fenced ; puis résultat consultable du demandeur via un Event terminal et une Task projetée. **PLANNED / NOT IMPLEMENTED** pour request, outcome, UserCreated, Event terminal, task, artifact, GET et worker Registration. Séparément, le succès modifierait l'autorité Binding puis alimenterait la représentation courante. Le code actuel de Binding est un consumer de faits direct, non Event→Task. Le plan prescrit REG.0 Event→Task pour CURRENT_BINDING : c'est un objectif documentaire, pas une chaîne en place. Le plan dit aussi que le GET Registered n'est visible que si CURRENT_BINDING READ correspond encore à E/U/B exact ; ce contrôle rend la visibilité du résultat dépendante d'une seconde matérialisation et peut temporairement donner 404 après un succès committé. Le rejet reste visible au créateur E sans binding courant. Le besoin de consulter sa demande ne justifie aucune API anonyme sur l'outcome primaire.

**Contradictions constatées.** Le [POT E2E Plan](../POT_E2E/Step_Plan.md) exige une séquence READ stricte capacités→AUTH@V→READ_POT@V ; le [PotQueryController](../../../../app/supra-http-read-query/src/main/java/com/kartaguez/pocoma/supra/http/read/query/PotQueryController.java) effectue d'abord `ExternalIdentityResolverPort.findUserId(E)` via l'adapter JPA primaire. L'affirmation générale « GET protégés exclusivement READ » dans les audits/plans ne décrit donc pas ce call site. La résolution self `CURRENT_BINDING(E)` et la résolution E→U du GET Pot coexistent sans le même chemin. La version [READ V9](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V9__current_external_identity_binding.sql) imposait un B non nul pour DETACHED ; [V11](../../../../app/infra-read-persistence/src/main/resources/db/read-store/migration/V11__current_binding_canonical_detached.sql) l'a corrigé : ne pas reprendre cet ancien constat du [completed audit](../../completed/WRITE_ADMISSION/Binding_Canon_Alignment_Audit.md) comme état actuel. De même, la reconstruction R0 et la provenance ont été renforcées par [WRITE V22](../../../../app/infra-persistence-jpa/src/main/resources/db/migration/V22__repair_binding_history_and_contract.sql) et READ V12/V13. Le [Registration Plan](../REGISTRATION/Step_Plan.md) dit « décisions d'implémentation ouvertes : aucune » ; son propre contrôle Registered dépend de la convergence CURRENT_BINDING, tandis que l'[audit précédent](../REGISTRATION/Current_Binding_Registration_Architecture_Audit.md) signale une tension avec la consultabilité indépendante du résultat. Ce rapport constate la tension sans réviser le plan.
